# 我的HTTP与HTTPS学习笔记

参考资料：[HTTP messages](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Messages)、[HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html)、[TLS 1.3](https://www.rfc-editor.org/rfc/rfc8446.html)。

## 什么是HTTP
HTTP 是客户端和服务器交换信息的协议。客户端通过请求说明想做什么，服务器通过响应返回处理结果。

- 在 JotangNote 中，浏览器是客户端，后端程序提供服务
- HTTP 负责传输，请求和响应里的数据可以使用 JSON

## 问题1：请求和响应有哪些部分
以 HTTP/1.1 为例，请求和响应都包括起始行、头部、空行和可选的消息体。

### HTTP 请求
- 请求行：方法、请求目标和协议版本，例如 `GET /api/notes/1001 HTTP/1.1`
- 请求头：提供主机、认证、内容格式等信息
- 空行：分隔头部和消息体
- 请求体：提交的数据，例如笔记标题和正文

### HTTP 响应
- 状态行：协议版本和状态码，例如 `HTTP/1.1 200 OK`
- 响应头：提供返回格式、缓存规则等信息
- 空行：分隔头部和消息体
- 响应体：返回的数据或错误说明

不是每个请求或响应都有消息体；HTTP/2、HTTP/3 的传输格式不同，但仍有方法、头部、状态码和消息体这些概念。

## 问题2：提交长篇笔记用GET还是POST
提交一篇新笔记用 `POST`，把标题和正文放在请求体中。

- `GET` 主要用于读取数据，例如查询笔记详情
- `POST` 适合提交数据，让服务器创建或处理资源
- 选择 POST 主要是因为“提交新笔记”的含义，而不只是正文比较长
- 不把长正文放进 URL；请求体也有大小限制，需要结合后端配置处理

例如：

```text
POST /api/notes
Content-Type: application/json

{"title":"Redis笔记","content":"这里是笔记正文"}
```

## 问题3：状态码是什么，什么时候使用
状态码是响应中的三位数字，用于说明请求的处理结果。

- `2xx`：成功
- `3xx`：重定向，或与条件请求有关的结果
- `4xx`：请求、认证、权限等方面的问题
- `5xx`：服务器或其依赖出现问题

| 状态码 | 含义 | JotangNote 示例 |
| --- | --- | --- |
| 200 | 请求成功 | 查询笔记成功 |
| 201 | 资源已创建 | 新笔记保存成功 |
| 202 | 已接受，处理未完成 | 后台摘要任务已提交 |
| 204 | 成功，无响应体 | 删除笔记成功，不返回正文 |
| 400 | 请求不合法 | 缺少必填字段、JSON 格式错误 |
| 401 | 未认证或认证无效 | 没有登录、登录凭证失效 |
| 403 | 禁止访问 | 已登录，但无权查看私有笔记 |
| 404 | 资源不存在 | 笔记不存在 |
| 409 | 当前状态冲突 | 笔记版本已变化，拒绝覆盖 |
| 413 | 请求内容过大 | 正文或附件超过限制 |
| 429 | 请求过于频繁 | 触发限流 |
| 500 | 服务器内部错误 | 后端出现未处理的异常 |
| 503 | 服务暂时不可用 | 服务过载或暂时无法提供服务 |

## 什么是HTTPS
HTTPS 是通过 TLS 保护的 HTTP，主要提供传输加密、完整性校验和服务器身份验证。

- HTTP 明文传输，途中可能被读取或修改
- HTTPS 保护传输过程，但不代替登录、权限检查和数据库中的密码保护
- POST 本身也不提供加密，登录和提交笔记都应通过 HTTPS

## HTTPS问题：加密过程是怎么样的
以现代 TLS 连接的一般流程理解：

1. 客户端与服务器协商支持的 TLS 参数，并交换密钥协商所需的信息
2. 服务器提供证书等证明，客户端校验证书信任链、有效期和域名
3. 双方通过密钥协商和派生，得到用于本次连接的通信密钥
4. 握手完成后，用对称加密保护 HTTP 数据，并校验数据完整性

非对称密码技术主要用于身份验证和密钥协商，对称加密用于后续大量数据传输；服务器私钥不会直接发送给客户端。

## 实践注意事项
- 浏览器开发者工具的 Network 页面可以查看方法、URL、头部、状态码和响应内容
- 任务刚入队时显示“已提交”或“处理中”，处理完成后再显示“修改成功”
- 网络超时不一定代表服务端没有处理，重复提交需要考虑业务去重
- HTTPS 不会自动把数据库中的明文密码变安全，密码应使用专门的密码哈希方案
