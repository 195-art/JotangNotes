# 我的AI Agent学习笔记

参考资料：[Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)、[Memory overview](https://docs.langchain.com/oss/python/concepts/memory)。

## 什么是AI Agent
AI Agent 是让大模型结合工具、上下文和任务流程来完成事情的程序，可以查询数据、操作文件，也可以根据执行结果继续下一步。

- 大模型：理解需求，选择下一步操作
- 工具：实际执行查询、修改、生成文件等任务
- 上下文：提供当前问题、历史信息和工具返回的结果
- 流程控制：安排调用顺序，处理失败和停止条件

## 问题1：大模型怎么进行更多操作
把外部功能封装成工具，告诉模型工具名称、用途和参数。模型提出工具调用请求，后端执行后把结果返回，再由模型继续处理。

> 用户提出需求 → 模型选择工具 → 后端执行 → 返回结果 → 模型继续处理或回答

例如让 JotangNote 总结一篇笔记：

1. 模型选择 `getNote(noteId)`，请求读取笔记
2. 后端检查当前用户的权限，再查询笔记内容
3. 把查询结果交给模型，模型生成摘要
4. 如果需要保存，再调用 `saveSummary(noteId, summary)`

- 模型输出“已经保存”不代表真的保存，需要根据工具的执行结果判断
- 工具可以是数据库查询、HTTP API、文件操作，不一定需要控制电脑
- 删除或覆盖笔记这类操作，可以先让用户确认；权限检查仍由后端完成

## 问题2：大量历史信息怎么保存
把信息存到模型之外，需要时再取回相关内容，不必每次把全部历史都发给模型。

- MySQL：保存对话、任务状态、用户偏好等长期记录
- 文件或对象存储：保存原始笔记、附件和工具生成的文件
- 检索索引：按关键词或语义查找相关内容，语义检索可以使用向量索引
- 上下文整理：保留近期对话，把较早的内容压缩成摘要

例如用户问“我以前写过哪些 Redis 笔记”，先检索相关笔记，只把匹配的片段交给模型。这个方式通常叫检索增强生成（RAG）。

长期信息存储在外部，模型当前能看到什么，取决于这次提供的上下文；摘要可能遗漏细节，重要信息要能查回原文。

## JotangNote 中可以做什么
- 总结笔记：读取正文，生成摘要和关键词
- 查找笔记：把自然语言需求转换成检索条件
- 整理内容：根据已有笔记生成分类或目录建议

生成摘要如果耗时较长，可以通过 RabbitMQ 提交后台任务，前端显示任务状态。

## 实践注意事项
- 查询结果只包含当前用户有权访问的数据，用户身份由后端确定
- 笔记内容作为待处理的数据，不能让里面的文字随意改变工具权限
- 保存工具调用结果和失败原因，方便重试与排查
- 限制工具调用次数和超时时间，避免任务一直运行
